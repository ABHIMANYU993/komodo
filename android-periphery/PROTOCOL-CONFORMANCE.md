## 1. Transport & Framing Layout

Komodo communicates exclusively over WebSocket binary frames (`tungstenite::Message::Binary`). Text frames are never used for protocol messages.

### Wire Envelope Encoding

Every message transmitted over the WebSocket consists of a payload followed by a single-byte `TransportMessageVariant` discriminator at the very end of the frame:

```
+------------------------------------------+------------------------------+
|               Message Payload            |  TransportMessageVariant (1B) |
+------------------------------------------+------------------------------+
```

#### Discriminator Values (`TransportMessageVariant`):
- `0x00`: `Login`
- `0x01`: `Request`
- `0x02`: `Response`
- `0x03`: `Terminal`

### Sub-Framing by Variant

#### 1. Login Frame (`Variant = 0x00`)
```
+-------------------+---------------------------+-----------------------+---------------------+
| Inner Payload     | LoginMessageVariant (1B)   | Response Status (1B)  | Transport Var (0x00)|
+-------------------+---------------------------+-----------------------+---------------------+
```
Where `Response Status`:
- `0x00`: `Ok`
- `0x01`: `Err` (Payload is serialized `mogh_error::Serror` JSON)
- `0x02`: `Pending` (Not permitted in Login frames)

`LoginMessageVariant` values:
- `0x00`: `Success`
- `0x01`: `Nonce` (32 bytes)
- `0x02`: `Handshake` (Noise payload)
- `0x03`: `OnboardingFlow` (1 byte: `0x00` = false, `0x01` = true)
- `0x04`: `PublicKey` (SPKI format string bytes)
- `0x05`: `V1PasskeyFlow` (deprecated v1)
- `0x06`: `V1Passkey` (deprecated v1)

#### 2. Request Frame (`Variant = 0x01`)
```
+------------------------------------------+-----------------------+---------------------+
| JSON PeripheryRequest Payload            |  Channel UUID (16B)   | Transport Var (0x01)|
+------------------------------------------+-----------------------+---------------------+
```
- Channel UUID is 16 bytes Big-Endian.
- Request payload is JSON: `{"type": "<Variant>", "params": { ... }}`.

#### 3. Response Frame (`Variant = 0x02`)
```
+----------------------------------+----------------------+--------------------+---------------------+
| JSON Encoded Response / Serror   | Response Status (1B) | Channel UUID (16B) | Transport Var (0x02)|
+----------------------------------+----------------------+--------------------+---------------------+
```
Where `Response Status`:
- `0x00`: `Ok` (JSON data)
- `0x01`: `Err` (JSON `mogh_error::Serror`)
- `0x02`: `Pending` (In-progress keepalive sent every 4s, empty payload)

#### 4. Terminal Frame (`Variant = 0x03`)
```
+----------------------------------+----------------------+--------------------+---------------------+
| PTY Raw Binary Stream / Serror   | Response Status (1B) | Channel UUID (16B) | Transport Var (0x03)|
+----------------------------------+----------------------+--------------------+---------------------+
```

## 2. Zero-Trust Identifiers & Prologue Construction

The handshake binds cryptographic authentication to the active transport parameters using a connection-unique SHA-256 prologue hash:

```
Prologue = SHA-256("noise-wss-v1|" + host + "|" + query + "|" + accept + "|" + nonce)
```

Where:
- `host`: The Host header (e.g. `192.168.1.100:8120` or `komodo.example.com`).
- `query`: The URL query string formatted as `server=<connect_as>` (e.g. `server=Redmi_Note_10_Pro`).
- `accept`: The `Sec-WebSocket-Accept` header string from the HTTP 101 Switching Protocols response.
- `nonce`: A 32-byte cryptographically secure random array generated by Core and sent in `LoginMessage::Nonce`.

Both Core and Periphery must independently calculate the exact same prologue bytes. Any mismatch results in a Noise decryption failure on message 2 or 3.

## 3. The Authentication & Onboarding State Machine

```
   Periphery (Initiator)                           Core (Responder)
           |                                               |
           |====== Outbound WebSocket Upgrade (HTTP) =====>|
           |  GET /ws/periphery?server=<connect_as>        |
           |<===== 101 Switching Protocols (accept) =======|
           |                                               |
           |<----- LoginMessage::OnboardingFlow(bool) -----|
           |                                               |
   +-------+-------+                               +-------+-------+
   | onboarding?   |                               | server state? |
   +---------------+                               +---------------+
           |                                               |
    [IF FALSE: Normal Login]                        [IF FALSE: Normal Login]
           |<----- LoginMessage::Nonce([u8; 32]) ----------|
           |                                               |
           |-- LoginMessage::Handshake(m1: 32B) ---------->|  (Noise -> e)
           |                                               |
           |<-- LoginMessage::Handshake(m2: 96B) ----------|  (Noise <- e, ee, s, es)
           |   * Periphery validates Core public key       |
           |                                               |
           |-- LoginMessage::Handshake(m3: 64B) ---------->|  (Noise -> s, se)
           |                                               |   * Core validates Server key
           |                                               |
           |<----- LoginMessage::Success ------------------|  (Noise Handshake complete)
           |                                               |
           |====== Transition to Message Loop =============|
           |                                               |
           |                                               |
    [IF TRUE: Onboarding Flow]                      [IF TRUE: Onboarding Flow]
           |   * Requires PERIPHERY_ONBOARDING_KEY         |
           |                                               |
           |<----- LoginMessage::Nonce([u8; 32]) ----------|
           |                                               |
           |-- LoginMessage::Handshake(m1: 32B) ---------->|  (Noise -> e using onboarding_key)
           |                                               |
           |<-- LoginMessage::Handshake(m2: 96B) ----------|  (Noise <- e, ee, s, es)
           |                                               |
           |-- LoginMessage::Handshake(m3: 64B) ---------->|  (Noise -> s, se)
           |                                               |   * Core validates onboarding key
           |                                               |
           |<----- LoginMessage::Success ------------------|
           |                                               |
           |-- LoginMessage::PublicKey(persistent_spki) -->|  (Server identity registered)
           |                                               |   * Core updates DB with public key
           |<----- LoginMessage::Success ------------------|
           |                                               |
           |====== TCP Close & Reconnect ==================|  (Core closes socket)
           |   * Next connection uses Normal Login Flow    |
```

## 4. Post-Authentication Multiplexing & Heartbeats

1. **Keepalive Pings**:
   - Every 5 seconds of inactivity, Periphery sends a standard WebSocket `Ping` frame.
   - Core replies with `Pong`.
2. **Channel UUID Routing**:
   - Each Core request arrives tagged with a 16-byte UUID.
   - Long operations (e.g., stats collection or terminal creation) must emit a `Pending` frame (`Status = 0x02`) every 4 seconds.
   - Core's channel timeout is **10 seconds**. Failure to emit `Pending` or final response within 10s causes Core to abort the request.
3. **Response Dispatch**:
   - Responses are mapped to the requesting Channel UUID.
   - `Ok(T)` serializes `T` as JSON, appends `0x00`, channel UUID (16B), and `0x02`.
   - `Err(E)` serializes `mogh_error::Serror` as JSON, appends `0x01`, channel UUID (16B), and `0x02`.
